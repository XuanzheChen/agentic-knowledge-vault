## 什么是后训练？

后训练（Post-training）是在基础模型之上，针对实际使用方式和目标行为继续进行训练的阶段。它主要用于提升模型的指令遵循、对话、推理、偏好对齐、安全性、工具使用和 Agentic Behavior 等能力。

> **后训练的核心是进一步塑造模型在真实任务中的行为方式和任务表现。**

---

## 从目标与反馈角度看，后训练到底在做什么？

预训练得到的 Base Model 已经学习了大量知识、表示和潜在行为，但“能够生成某种行为”并不等于“在合适的任务中稳定选择这种行为”。后训练的核心因此可以理解为 **Behavior Shaping（行为塑形）**：通过外部定义的目标与反馈，调整模型的行为分布，使期望行为概率提高、不期望行为概率降低。

后训练通常同时包含两类作用：

- **Capability Elicitation**：把模型原本偶尔能够表现出的能力，变成更稳定、可控的行为。
- **Capability Improvement**：通过新的训练经验与反馈，进一步增强推理、工具使用等能力。

其基本链路是：

> **Desired Behavior → Feedback → Training Signal → Optimization → Model Behavior → Evaluation**

其中，**Desired Behavior** 描述希望模型具有什么行为，例如正确性、指令遵循、帮助性、安全性、推理能力和工具使用能力；**Feedback** 则负责把这些抽象目标转成可学习的信号。

常见反馈可以从两个维度理解：

| 维度 | 主要形式 |
| --- | --- |
| **反馈来源** | Human、AI、规则 / Verifier、Environment |
| **反馈形式** | Demonstration、Preference、Reward / Score、Success-Failure Outcome、Critique / Principle |

不同训练范式本质上是在使用不同形式的反馈：SFT 主要通过 **Demonstration** 告诉模型“应该怎样做”；偏好学习通过 **Preference** 告诉模型“哪个行为更好”；RL-based Post-training 则利用 **Reward / Outcome** 让模型通过自身 Rollout 与反馈进一步优化策略。

反馈还可以分为：

- **Outcome Feedback**：关注最终结果是否正确或任务是否完成。
- **Process Feedback**：关注中间推理、工具调用或执行轨迹是否合理。

后训练的难点并不只是“如何最大化奖励”，而是 **反馈信号是否真实代表目标行为**。如果代理指标设计不合理，模型可能出现 Reward Hacking、Length Bias、Sycophancy、Over-refusal 等问题。因此现代后训练通常是多目标优化，需要同时平衡正确性、帮助性、安全性、效率等目标，并通过持续评估修正数据与反馈设计。

> **后训练可以看作：用外部反馈把“模型会什么”进一步转化为“模型在什么情况下应该怎样做”。**

## 后训练有哪些常用范式？

现代后训练常见的范式包括：

1. **监督微调（SFT / Instruction Tuning）**：使用高质量的输入—目标输出样本，直接学习期望的回答或行为。
2. **偏好学习 / 偏好优化（Preference Learning / Optimization）**：利用回答之间的偏好关系，让模型更倾向于符合目标的输出。
3. **基于强化学习的后训练（RL-based Post-training）**：根据人类反馈、AI 反馈、可验证结果或环境反馈形成奖励信号，进一步优化模型行为。
4. **Rejection Sampling / Self-training**：由模型生成多个候选结果，经过规则、模型或人工筛选后，将高质量结果继续用于训练。
5. **蒸馏（Distillation）**：利用更强模型的输出或行为，将能力迁移到目标模型中。蒸馏也可以用于其他训练阶段，并不只属于后训练。

合成数据、数据过滤与数据配比通常作为贯穿这些范式的**数据策略**，而不是独立的训练阶段。

## 微调数据从哪里来，如何判断其训练价值？

微调数据通常来自：

1. 人工标注的业务数据。
2. 线上真实交互日志，尤其是模型出错后由人工修正的数据。
3. 领域专家专门构造的数据。
4. 更强模型生成的合成数据，但需经过规则过滤、模型评审和人工抽检。
5. 用于补充通用能力的公开数据集。

判断一批数据是否值得训练，不应主要看数量，而应先看它是否针对当前模型真实的失败模式。模型缺少最新知识时，应优先使用 RAG；真正适合训练的是模型在获得正确上下文后，仍稳定出现能力或行为问题的场景。

数据质量主要看：

- **正确性**：最终答案和中间执行轨迹都正确。
- **标注一致性**：相同场景不能产生完全不同的目标行为。
- **覆盖率**：覆盖真实业务的常见问题、困难问题和边界情况，而非堆积容易样本。
- **新颖性**：去除重复和高度相似样本。
- **分布一致性**：尽量贴近线上真实用户。

最后先做小规模微调，用独立测试集与原模型比较，确认预先定义的核心错误是否下降，并检查是否出现其他能力退化。若不能带来明确的真实业务指标增益，即使数据量很大，也未必值得训练。

> **训练数据的核心不是“多”，而是“正确、一致、覆盖真实失败分布，并且确实能提供新的学习信号”。**
