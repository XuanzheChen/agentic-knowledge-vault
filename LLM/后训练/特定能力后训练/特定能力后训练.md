## 什么是特定能力后训练？

特定能力后训练是指围绕某一种目标能力，专门设计 **Task、Data、Feedback / Reward、Environment 与 Evaluation**，使模型在该能力上的行为更加稳定或进一步提升。

它并不是新的训练阶段，而是后训练中的一种组织方式：同样可以使用 SFT、偏好学习、RL 等范式，但不同能力会因为任务结构和反馈可验证性不同而采用不同的数据与训练重点。

## 当前常见的特定能力后训练主要针对哪些能力？

| 能力目标 | 数据侧重点 | 反馈 / Reward 侧重点 | 训练倾向 |
| --- | --- | --- | --- |
| **Reasoning** | 数学、代码、逻辑、STEM 难题，长推理轨迹与 Rollout | 最终答案或过程是否可验证 | Verifiable Reward + RL |
| **Reasoning Efficiency** | 不同难度任务、不同推理预算、Thinking / Non-thinking 样本 | 正确率与推理成本共同考虑 | RL / Preference，强调 Accuracy-Compute Trade-off |
| **Coding / Software Engineering** | Repository、Issue、Patch、测试、编译与调试轨迹 | Unit Test、Integration Test、Execution Result | Execution-driven RL + SFT |
| **Tool Use** | Tool Schema、参数、Observation、多工具轨迹、异常返回 | Tool Selection、Argument、最终任务结果 | Trajectory SFT + Interactive RL |
| **Search / Deep Research** | 多跳检索、Query Reformulation、网页阅读、证据与 Citation | Answer Correctness、Evidence、Citation | End-to-end Agent RL + Grader |
| **Long-Horizon Agent** | 长任务轨迹、Replanning、Error Recovery、环境状态变化 | 最终 Outcome + 中间过程 | Long-horizon RL，重点解决 Credit Assignment |
| **Computer Use** | Screenshot、GUI State、Mouse / Keyboard Action | 最终应用或网页状态 | Imitation / Trajectory SFT + Environment RL |
| **Multi-Agent Coordination** | Delegation、Handoff、角色分工、共享状态与通信 | Team Outcome、Individual Contribution | Coordination / Multi-Agent RL，强调 Credit Assignment |
| **Factuality / Groundedness** | 已知、未知、冲突信息、检索证据、Citation | 事实正确性、Groundedness、Calibration | Preference / Verifier / Judge |
| **Instruction Following** | 多约束指令、格式、权限和 Instruction Hierarchy | Constraint Satisfaction | SFT + Preference / RL |
| **Safety / Alignment** | Policy、边界案例、Jailbreak、Over-refusal 对照 | Policy Compliance、Safe Completion | Safety SFT + Preference / RM / RL |
| **Taste / Judgment** | 写作、设计、代码风格、Artifact 质量 | Human / AI Preference、Expert Rubric | Preference Learning / RLAIF |
| **Multimodal / Embodied** | Image、Text、Sensor、Action 与环境状态 | 任务完成或物理结果 | Imitation Learning + Environment RL |

## 为什么不同能力会采用不同的数据与训练侧重点？

关键取决于三件事：

1. **可验证性（Verifiability）**  
   如果结果可以自动判断，例如数学答案、代码测试，适合使用大规模 Rollout + Verifier + RL。若质量难以硬规则化，例如写作、设计和 Taste，则更依赖 Human / AI Preference、Reward Model 或 Judge。

2. **交互性（Interactivity）**  
   单轮任务可以用 Prompt-Response 数据；Tool Use、Search、Computer Use 和 Agent 任务则需要 **State → Action → Observation → ... → Outcome** 的 Trajectory，并常常需要真实或模拟 Environment。

3. **任务跨度（Horizon）与 Credit Assignment**  
   任务越长，最终 Reward 越难判断是哪一步 Action 导致成功或失败。因此 Long-Horizon Agent 和 Multi-Agent 训练更关注过程反馈、环境状态以及 Credit Assignment。

因此，专项 Post-training 不存在统一的“最佳算法”，应先确定目标能力的 **Task Structure、Feedback Quality 与 Verifier / Environment**，再选择训练范式。

## 当前专项 Post-training 的总体趋势是什么？

现代专项 Post-training 正从静态 Dataset 逐渐走向：

> **Environment → Rollout → Grader / Verifier → Reward → Optimization**

主要趋势可以概括为：

- **能力越容易自动验证，越适合 RL**：数学、代码最典型。
- **能力越交互式，训练单位越从 Response 变成 Trajectory**：Tool Use、Research、Computer Use、Agent 都属于这一类。
- **能力越难验证，越依赖 Preference、Reward Model 与 Judge**：Safety、Taste、复杂 Research 等更明显。
- **Agent 能力越来越依赖 Environment**：训练重点从“生成一个答案”转向“在真实或模拟环境中连续行动并完成任务”。
- **数据、Reward、Environment 与 Evaluation 的重要性上升**：算法只是训练系统的一部分，反馈信号是否可靠往往决定最终能力上限。

> **专项 Post-training 的核心不是为每种能力发明一个新算法，而是为目标能力设计最合适的数据、反馈、环境和优化闭环。**
