## 为什么要做偏好学习？

SFT 通过 Demonstration 告诉模型“一个期望回答是什么样”，但许多开放式任务不存在唯一标准答案。相比要求标注者写出唯一目标答案，偏好学习更关注：**对于同一个输入，多个可接受输出中哪个更好。**

最典型的数据形式是 Pair-wise Comparison：

> `(x, y_w, y_l)`，其中 `y_w` 是更受偏好的回答，`y_l` 是较差回答。

这种相对比较通常比给回答打绝对分数更稳定，也能表达正确性、帮助性、安全性、风格等难以写成唯一 Ground Truth 的目标。

偏好学习的主要作用包括：

- **行为选择与对齐**：提高符合目标偏好的输出概率，压低不期望行为。
- **Capability Elicitation / 表现筛选**：模型可能已经能够偶尔生成正确推理或高质量回答，偏好训练帮助它更稳定地选择这些行为。
- **能力改善**：当偏好数据提供了新的、有效的训练信号时，也可能进一步增强推理、工具使用等能力；但它并不会凭空补充模型缺失的事实知识。

因此偏好学习的核心不是“学习一个标准答案”，而是**学习怎样在多个可能行为之间做更好的选择，并重塑模型的输出分布**。

## 偏好的来源有哪些？

偏好主要可以来自以下几类来源：

1. **Human Feedback**：由人工比较多个候选回答，最接近真实用户判断，但成本高、速度慢，也存在标注者差异。
2. **AI Feedback**：由更强模型或 Judge Model 根据 Rubric、原则或 Constitution 评价候选回答，易于扩展，但会继承评价模型自身的偏差。
3. **规则 / Constitution**：依据显式规则、安全规范或任务约束判断优劣，适合标准较清晰的场景。
4. **Verifier / Environment**：利用数学答案、单元测试、任务成败等可验证结果对候选进行排序。严格来说这类信号不一定属于传统“主观偏好”，但可以转化为 preference pair，也常与现代偏好训练结合使用。

实际系统通常会混合多种来源，例如人工定义评价准则，再由 AI Judge 扩展标注，并用可验证结果纠正主观判断。

---

## 偏好的评价标准是多维的吗？

是。真实 Assistant 的“更好”通常不是单一指标，而是多个目标的组合，例如：

- Correctness / Factuality
- Instruction Following
- Helpfulness
- Honesty
- Safety / Harmlessness
- Conciseness / Style
- Format / Tool-use Correctness

这些维度之间可能冲突。例如一个回答可能更详细但更啰嗦，另一个更简洁但遗漏信息；一个回答更有帮助，但可能触碰安全边界。

因此高质量 Preference Annotation 需要明确 **Rubric 与优先级**，而不是简单让标注者“选择更喜欢的回答”。否则 Reward Model 或 Preference Objective 很容易把长度、语气、自信程度等表面特征错误地当成真正质量。

## Reward Model 如何从偏好中学习 Response 的好坏？

经典 Reward Model（RM）通常使用 Transformer Backbone 加一个 Scalar Reward Head。它分别读取 `(x, y_w)` 与 `(x, y_l)`，得到：

\[
r_w=r_\phi(x,y_w),\qquad r_l=r_\phi(x,y_l)
\]

RM 并不是直接生成 `y_w`，而是学习给一个完整 Response 打分。经典 Pair-wise Reward Modeling 常使用 Bradley-Terry / Logistic Preference Loss：

\[
P(y_w \succ y_l\mid x)=\sigma(r_w-r_l)
\]

\[
\mathcal{L}_{RM}=-\log\sigma(r_w-r_l)
\]

训练目标就是让偏好回答的分数高于被拒绝回答，即增大 `r_w-r_l`。因此它在目标上类似一个 pair-wise 二分类 / 排序问题，但结构上更准确地说是：**分别给两个 Response 输出标量 Reward，再通过 Reward 差学习偏好关系。**

训练好的 RM 可以用于 RL 的 Reward Function、Rejection Sampling、候选排序或评估。

## Reward Model 路线有哪些方法？

显式 Reward Model 路线可以理解为两步：

> **Preference → Reward Model → Reward → Policy Optimization**

### 经典路线

经典 RLHF 使用 **Scalar Reward Model**：通过 pair-wise preference 和 Bradley-Terry Loss 学习 `r(x,y)`，然后用 PPO 等 RL 方法最大化该 Reward。

### 现代 Reward Model 方向

现代 RM 不再只有“完整回答 → 一个标量”这一种形式，常见扩展包括：

- **Outcome Reward Model（ORM）**：主要评价最终回答或最终任务结果。
- **Process Reward Model（PRM）**：评价中间推理步骤或执行过程，为长推理提供更细粒度反馈。
- **Multi-objective / Multi-head RM**：分别建模正确性、帮助性、安全性、风格等维度，再进行聚合。
- **Generative / Reasoning Reward Model**：先生成 Critique、Rubric 或推理过程，再给出偏好判断或 Reward，提高复杂任务上的评价能力与可解释性。

在 Policy Optimization 一侧，显式 RM 提供的 Reward 可以被 PPO、GRPO 等不同 RL 优化方法使用；**PPO / GRPO 是策略优化算法，不是 Reward Model 本身。**

如果任务本身能够直接得到可靠的 Verifiable Reward，则可以跳过学习式 RM，这通常属于更广义的 RL-based Post-training，而不是显式 Reward Model 路线。

## 直接偏好优化方法有哪些？

Direct Preference Optimization 的共同思想是：**不显式训练独立 Reward Model，也不必先运行传统 RM + RL 两阶段流程，而是直接利用偏好数据更新 Policy。**

其中 DPO（Direct Preference Optimization）严格来说是一个具体算法；“DPO family / DPO-style methods”是对一批直接偏好优化方法的宽泛称呼。常见方法包括：

- **DPO**：利用 chosen / rejected pair 与 Reference Policy 的相对 log-prob 直接优化 Policy，是最经典的直接偏好优化方法。
- **IPO（Identity Preference Optimization）**：重新设计偏好目标，缓解某些 DPO 过度优化和噪声偏好问题。
- **SimPO**：使用长度归一化的隐式 Reward，并去掉 Reference Model，同时加入目标 Margin。
- **ORPO**：将监督学习与偏好约束合并在一个训练目标中，无需额外 Reference Model。
- **CPO 等 Contrastive Preference 方法**：通过对比 chosen 与 rejected 的概率关系直接进行对齐。
- **KTO**：只需要 desirable / undesirable 的二元反馈，不要求标准 pair-wise 数据；通常归入更宽泛的 Direct Preference Alignment，而不属于严格的 pair-wise DPO 变体。

> **GRPO 不属于 DPO family。** GRPO 是 RL-based Policy Optimization 方法，更接近 PPO 这一侧。

## RLHF 和 RLAIF 在偏好学习中的位置是什么？

不宜简单把 RLHF、RLAIF 当作“Preference Learning 的两个子类”，因为它们同时描述了 **Feedback 来源 + 后续 RL 优化流程**。

经典流程可以写成：

> **RLHF：Human Preference → Reward Model → RL Policy Optimization**  
> **RLAIF：AI Preference → Reward Model（或直接 AI Reward）→ RL Policy Optimization**

因此偏好学习通常是 RLHF / RLAIF 中负责把“哪个回答更好”转成 Reward 或优化信号的关键环节，但 RLHF / RLAIF 的范围更大，还包含后续的 Policy Rollout 与强化学习更新。

从两个正交维度理解更清楚：

| 维度 | 典型形式 |
| --- | --- |
| **Feedback 来源** | Human、AI、Rule / Constitution、Verifier |
| **如何利用 Feedback** | Reward Modeling、Direct Preference Optimization、RL-based Optimization |

同样的 Human / AI Preference 也可以直接用于 DPO 等方法而不显式运行 RL。狭义上，这种训练更适合称为 Human / AI Preference Optimization，而不是传统的 RLHF / RLAIF。

## 为什么现代后训练越来越重视在线偏好学习？

这里需要区分：**离线偏好优化仍然非常常用，尤其是 DPO 一类方法；现代大规模或持续后训练只是越来越重视 Online / Iterative Preference Learning。**

离线训练使用固定数据集 `(x,y_w,y_l)`。随着 Policy 不断更新，旧数据逐渐不再代表当前模型会生成什么，形成 **Off-policy / Distribution Shift**：训练数据仍在纠正旧模型的问题，而新模型已经出现了新的错误模式。

在线或迭代偏好学习则不断循环：

> **Current Policy → 生成新候选 → Human / AI / RM 评价 → 新 Preference Data → 更新 Policy**

这样做的主要价值是：

- 数据更贴近当前 Policy 的真实输出分布。
- 能持续获得当前模型真正难分的 Hard Preference / Hard Negative。
- 模型能力提升后，可以同步提高任务难度与评价标准。
- 可以形成 Model → Data → Feedback → Model 的持续数据飞轮。

代价是生成、评价和训练系统更复杂，也更依赖 Judge / RM 的稳定性，因此离线与在线方法通常会结合使用。

## 偏好学习中需要注意哪些失败模式？

偏好学习优化的是 **Observed Preference / Reward Proxy**，它不一定完全等同于真正想要的模型质量，因此常见失败模式包括：

1. **Label / Judge Bias**：标注者或 AI Judge 偏爱长回答、分点、正式语气、自信表达等表面特征，模型最终学到 Style Bias 或 Length Bias，而不是真正的正确性。
2. **Sycophancy**：如果评价者更喜欢“认同用户”的回答，模型可能学会迎合用户，即使用户的前提是错误的。
3. **Reward Hacking / Specification Gaming**：Policy 学会利用 Reward Model 或评价规则的漏洞获得高分，而不是真正完成目标。
4. **Reward Model Overoptimization**：随着 Policy 对代理 Reward 优化过强，RM Score 继续上升，但真实人工质量反而下降，因此经典 RLHF 常需要 Reference Policy、KL Constraint 等机制限制漂移。
5. **Preference Inconsistency / Noise**：不同标注者可能给出相反偏好，同一个人也可能在不同时间做出不同判断；多维目标还可能产生非传递偏好。
6. **Distribution Shift**：Preference Dataset 来自旧 Policy 或特定任务分布，新模型和真实线上请求改变后，原有偏好信号可能失效。
7. **Over-refusal / Capability Regression**：过度强化安全、风格或单一偏好目标，可能导致模型过度拒答、输出模式收缩，甚至损伤其他已有能力。

因此 Preference Learning 的关键不只是选择优化算法，而是持续检查：**谁在评价、依据什么标准、评价的数据是否代表当前 Policy，以及 Reward 是否仍然与真实目标一致。**
