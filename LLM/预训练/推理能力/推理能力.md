## 预训练为什么能让模型产生推理能力？

现代生成式 LLM 的核心预训练目标通常只是 **Next-Token Prediction（NTP）**：根据已有 Token 预测后续 Token。这个目标本身没有单独标注“这里要推理”，但要在复杂语料上持续降低预测误差，模型不能只学习局部词频，还需要逐渐捕捉更深层的结构。

例如，语料中会大量出现数学解题、代码、证明、因果说明、条件关系和跨句依赖。为了预测这些文本的后续内容，模型需要学习：

- 实体、概念和语义表示；
- 数量、条件、因果和逻辑关系；
- 代码与算法中的状态变化和执行模式；
- 如何把多个已经学到的关系组合起来得到后续结果。

因此可以把预训练中的能力形成粗略理解为：

```text
大规模复杂语料
        ↓
Next-Token Prediction
        ↓
学习能够提高预测准确率的内部表示与变换
        ↓
语义 / 关系 / 数量 / 程序模式等可复用结构
        ↓
这些结构在新问题中被组合
        ↓
表现为基础推理能力
```

从“压缩”的角度也可以理解这一过程：相比逐条记忆训练样本，学习“加法”“蕴含关系”“函数调用”“变量状态变化”等可复用规律，能够更有效地解释和预测大量不同文本。不过，“预训练等价于发现真实世界规则”只是帮助理解的直觉，并不是严格保证；模型仍可能依赖表面模式、捷径或记忆完成任务。

模型规模、训练数据质量和多样性也会影响这种能力。更大的模型通常拥有更强的表示与组合能力，但不宜简单理解成“参数量到某个阈值后突然产生真正的逻辑模块”。很多看似突然出现的能力，也会受到评测指标、提示方式和数据分布影响。

因此，**预训练并不是显式地安装一个 Reasoning Module，而是在完成足够复杂的语言建模任务时，学到能够复用和组合的表示与计算模式；其中一部分在数学、逻辑、代码等任务上表现为推理能力。**

## 模型的推理能力为什么会表现成 CoT？还有哪些表现形式？

**推理能力不等于 Chain-of-Thought。** CoT 是把部分中间计算显式展开为 Token 序列的一种方式。

预训练语料中本来就存在大量“问题 → 推导步骤 → 结果”的文本，例如数学解题、证明、教程、Debug 过程和代码解释。因此语言模型会学到：面对某些问题时，合理的后续文本不是立刻给出答案，而是先生成若干中间步骤。

CoT 还有一个重要的计算作用：**已经生成的中间 Token 会重新成为后续生成的 Context，相当于为模型提供外部 Scratchpad。**

原本需要一次完成的复杂映射：

```text
问题 x → 答案 y
```

可以被展开为：

```text
问题 x
  ↓
中间结果 z1
  ↓  z1 已进入上下文
中间结果 z2
  ↓
最终答案 y
```

这样每一步只需完成相对局部的预测，并可以直接读取前面已经写出的计算结果。已有研究表明，让语言模型显式生成中间计算步骤，能够明显改善一部分多步计算和推理任务。

但 CoT 只是推理能力的一种外显形式，至少还可以区分以下几类：

| 形式 | 表现 | 特点 |
| --- | --- | --- |
| **直接作答 / 隐式计算** | 不输出中间步骤，直接得到答案 | 计算主要体现在 Transformer 的 Hidden State 变换中，外部无法直接观察其完整过程 |
| **自然语言 CoT** | “首先……然后……所以……” | 易读，可把中间结果作为 Scratchpad，但语言化步骤不一定忠实对应内部因果过程 |
| **结构化中间表示** | 方程、表格、符号推导、伪代码、程序代码 | 同样能充当外部计算空间，在数学和代码任务中往往比纯自然语言更精确 |
| **规划、检查与修正轨迹** | 分解问题、检查前一步、重新尝试 | 常见于更强的推理模型，也经常受到后训练或推理时策略的进一步强化 |

需要特别注意：**看到一段流畅的 CoT，不等于看到了模型内部真实、完整且忠实的“思维过程”。** 模型可能已经通过隐藏状态中的计算形成倾向，再生成一个看起来合理的解释；实验也发现 CoT 有时会遗漏真正影响答案的输入因素，甚至对错误答案进行事后合理化。

因此更准确的关系是：

$$
\text{Reasoning Capability} \neq \text{Natural-language CoT}
$$

CoT 可以参与计算，也可以提高一些任务的正确率，但它不是模型推理能力的唯一载体，更不能自动被当成完全可信的内部过程解释。

## 预训练阶段形成的 CoT 与后训练强化的 CoT 有什么异同？

预训练和后训练都可以影响 CoT，但学习信号和作用不同。

### 预训练：从语料中学习基础能力与推理模式

预训练主要依靠通用语料上的语言建模目标。模型在数学解题、代码、论文、教程等文本中自然接触到大量显式推导，因此可能学会：

```text
问题 → 中间步骤 → 答案
```

这样的序列模式，同时形成完成这些步骤所需要的基础表示与计算能力。

因此 Base Model 中往往已经存在一定推理能力，合适的 Few-shot CoT 或类似“step by step”的提示就可能把它诱发出来。但这种能力未必稳定：模型不一定知道什么时候应该展开推理，也没有被直接优化为“找到更高正确率的推理轨迹”。

### 后训练：直接塑造怎样推理、何时推理以及哪些轨迹更有效

后训练可以给模型更直接的任务信号，例如：

- **SFT / Reasoning Trace Fine-tuning**：直接学习高质量的“问题—推导—答案”轨迹；
- **Self-training / Distillation**：从模型自身或更强模型生成的正确推理轨迹中继续学习；
- **Outcome / Process Supervision**：根据最终答案或中间步骤质量提供反馈；
- **RL-based Post-training**：根据可验证答案或其他奖励，让能够得到更高奖励的推理策略被强化。

因此后训练并不只是让回答“看起来更像 CoT”。它可以改变模型实际采用的策略，例如问题分解、反思、验证、重新尝试和推理长度分配。DeepSeek-R1 一类工作进一步表明，在合适的可验证奖励下，RL 可以强化甚至产生训练者没有逐步示范的推理行为。

两者可以这样区分：

| 维度 | 预训练中的 CoT / Reasoning | 后训练后的 CoT / Reasoning |
| --- | --- | --- |
| **主要学习信号** | 通用语料的 NTP 等自监督目标 | 推理示范、偏好、正确答案、过程或环境奖励 |
| **能力来源** | 学习语料中的知识、关系、程序和推导模式 | 在基础能力上进一步选择、强化或学习任务有效的策略 |
| **是否主动优化正确推理** | 通常不是，目标首先是预测训练文本 | 可以直接针对任务正确率或过程质量优化 |
| **行为稳定性** | 可能需要特定 Prompt 才容易诱发 | 通常更容易在合适任务上稳定进入推理模式 |
| **CoT 形态** | 更接近训练语料中已有的文本模式 | 可以被塑造成更长的探索、自检、验证或特定格式 |

两者也不是完全割裂的。后训练仍然建立在 Base Model 已经学到的语言、知识、表示和计算能力上；反过来，后训练也可能真正扩展模型的推理策略，而不只是把预训练已有能力“调用出来”。因此把关系简化成“预训练负责能力、后训练只负责格式”是不准确的。

更合适的理解是：

```text
预训练
→ 建立广泛的知识、表示和基础推理模式

后训练
→ 进一步诱发、筛选、强化并扩展有效的推理策略
```

另外，阶段边界也不是绝对的。例如 Quiet-STaR 通过带隐式 rationale 的 continued pretraining 提升推理能力，说明“推理训练”并不天然只能发生在传统后训练阶段；更关键的是使用了什么数据、目标和反馈信号。
